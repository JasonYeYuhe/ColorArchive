## 1. 一句话结论

**退出门前是分发冲刺,不是开发冲刺。** 代码只剩三件薄活:① 让 Track A 自己发的帖**链接预览不是空白/不掉链子**(支撑,非流量来源);② 把退出门信号**读干净**(否则白冲);③ 其余一律不做,除非 Track A 这周的量化目标已 100% 完成且仍有闲时。**不建新功能(红线)。** 把"可能没 PMF"当作被设计接住的结果,而不是用更多代码去推迟面对它。

---

## 2. 指导原则

1. **验证门控 + 分发优先**:本期成败看 Track A 流量,不看 commit 数。
2. **代码封顶**:Track 代码项总量刻意压到最小;每项前置问"它如何让这周的合格流量变多/信号更准",答不上 → 砍。
3. **冷启动 ≠ 优化**:现在是 0→1 获客,不是放大已有分享。任何"提升分享 CTR/SEO 排名"的项**对 07-15 的门无效**(索引/病毒循环都太慢),不计入本期。
4. **不牺牲验证数据换性能**(如 posthog defer 丢 pageview);不加横向工具/自建数据层;gate 前不 build Auditor。

## 3. 工作分解(精力配比 ≈ A:90% / 代码:10%)

### Track A — 分发执行(人工,本期 ≈ 全部重心,**量化 + tripwire**)
> review must-fix #3:"posting for the floor" 是愿望不是执行。必须定可测的每周输入,并设中途熔断。
- **目标(分母)**:窗口内 **/preorder UV ≥ 500** 或 **paywall 触发 ≥ 1000**。倒推 ≈ 3.5 周要从 ~0 做出 500 高意图点击。
- **量化输入(每周最低,按 distribution-plan-2026-06-15.md 的渠道)**:
  - Show HN / Reddit(r/web_design, r/Frontend, r/accessibility, r/SideProject 等)/ Dev.to / IndieHackers:**≥ 5 篇/周**,错峰、按各社区规则、披露 maker。
  - 定向社区(Designer/前端 Discord、X 设计圈):**≥ 10 条有价值互动 + 3 条带链接的帖/周**。

- **中途熔断(tripwire,~07-02 即窗口过半)**:若届时累计 /preorder UV < 250(或 paywall < 500),**说明当前渠道无效**——立即换渠道策略/换钩子,**不是继续等**。
- **问卷**:回收自助问卷(SURVEY1MON;**访谈已 DROP→问卷**)。定性退出门输入来自问卷。

## 5. 退出门 / 决策标准(~2026-07-15)—— **收紧:去掉无限延窗漏洞**

> review must-fix #2:原 "floor 未达标 → extend window" 会把硬门软化成可无限移动的目标。收紧如下。

**第一步 · 分母**:窗口内 **/preorder UV ≥ 500** 或 **paywall ≥ 1000**(任一 = 有效读)。

**第二步 · 决策矩阵:**
| 流量底线 | 真实刷卡预订(30 天) | 结论 |
|---|---|---|
| 达标 | **≥10** | ✅ 需求被验证 → 进 Track C,build Auditor(单点深做) |
| 达标 | **<10** | ❌ 产品没需求 → off-ramp(控成本维持 / 转移精力 / 打包评估) |
| **未达标** | 任意 | ⚠️ **判定:分发能力失败(非产品)。** 允许**至多一次有界再押**(换一套完全不同的渠道/钩子,再给 1 个明确窗口),**仍未达标 → 据此判项目"因获客失败"并 off-ramp。不得反复延窗。** |

**第三步 · 边界:** 7–9 笔(临界)读问卷——清晰 ICP + 共同强付费点可再延一窗复测,否则按 <10。≥10 但 ICP 分散 → 先锁买家类型再做。北极星 = 有证据支撑的 ICP + 真实付费。
