**核心:代码这阶段顶多 1–2 天(B-meas + D1)就做完,之后 3+ 周是几乎纯分发。** 任何"再优化一点"的代码冲动 = 在用舒适区逃避该做的难事。

## 1. 一句话结论

**这是分发冲刺,且分发必须【喂对人 + 够大量】。** 把对的 ICP(有 WCAG/可访问性合规痛点、会为审计工具付费的设计师/前端/团队)用审计痛点的钩子弄到 /preorder。代码只剩两件、~2 天做完:① 把退出门 funnel 读干净;② 保证创始人发出去的链接预览不空白。**其余时间一律分发,不写代码。不建新功能(红线)。**

---

## 2. 指导原则

1. **分发优先且喂对人**:本期成败 = 合格 ICP 流量 + 真实预订,不看 commit 数,也不看垃圾 UV。
2. **代码 ~2 天封顶**:B-meas + D1 做完即止;其后任何代码项前置问"它如何让这周多拿到**合格 ICP**流量 / 读门更准?"答不上 → 不做。
3. **冷启动 + 喂对人**:0→1 获客;钩子是审计痛点不是免费配色器;渠道是专业/a11y 社区不是泛流量站。
4. **不牺牲验证数据换性能;不加横向工具/自建数据层;gate 前不 build Auditor。**

## 3. 工作分解(时间配比 ≈ 代码 ~2 天 / 分发 余下全部）

### Track A — 分发执行(人工,本期几乎全部,**喂对人 + 填满工作周 + tripwire**)

- **目标(分母,已加渠道卫生)**:窗口内 **≥ 500 合格 ICP UV 到 /preorder**(或 paywall ≥ 1000)。"合格" = 来自 a11y/设计系统/专业设计前端语境,**不是** HN/泛 subreddit 的免费工具围观流量。倒推 ≈ **145 合格 UV/周**。
- **钩子(改)**:主推**可访问性审计的痛**(整盘 WCAG 手检多痛、合规要求、设计系统色彩可访问性),CTA → /preorder。**不是**"看我做的免费配色器"。免费工具只作二级钩子/信任锚,不作主获客。
- **渠道(改,匹配钩子+ICP)**:
  - **直接触达 ICP(主)**:有设计系统 / 在乎 a11y 合规的设计师、前端、设计系统/Design Ops 团队、做品牌/合规的小机构。LinkedIn + X 定向 + 冷邮件。
  - **专业/a11y 社区(主)**:a11y Slack/Discord、Design Systems 社区(如 design-systems Slack)、r/accessibility、相关 Discord;**以"贡献价值 + 谈审计痛"进入**,披露 maker。
  - **泛流量站(次,且不计入"合格"分母)**:HN/r/web_design 等可发,但视为品牌曝光,不当主获客,不污染读数。
- **量化输入(每周最低,填满 ~30+ 小时纯分发)**:
  - **≥ 40 条高度针对性 ICP 触达/周**(冷邮件 + LinkedIn/X DM,逐个研究对象,先给价值)。
  - **≥ 20 次真实社区贡献/周**(答 a11y/设计系统问题、参与讨论,非群发)。
  - **内容节奏**:≥ 2 篇围绕"可访问性审计痛点"的帖/周(LinkedIn/X/相关社区),导向 /preorder。
- **质量底线(防刷量)**:全部真实、针对性、先给价值、按社区规则、披露 maker——群发模板无效,UV 会自己证伪。
- **漏斗数学现实性(3.1 Pro 提醒)+ contingency**:这套量化里,~62 动作/周里大头要靠那 2 篇帖扛(DM/社区互动按 10% 点击仅约 6 UV/周,2 篇帖需扛 ~139 合格点击)——在小众 a11y/B2B 社区很难且易被判 spam。**故 contingency:若 tripwire(下条)显示帖子哑火,杠杆是 ① 大幅加大定向 DM/触达量(翻几倍)② 考虑付费微赞助**(a11y/设计系统 newsletter 或社区赞助,小额,把对的人买进 /preorder)。注意:撞墙也可能只证明"B2B 自然分发比 3.5 周慢"而非"没需求"——所以 tripwire 一旦触发就**换打法/加量/上付费**,别空等。
- **中途熔断(tripwire,~07-02 窗口过半)**:累计合格 /preorder UV < 250(或 paywall < 500)→ 当前渠道/钩子无效,**立即换/加量/上付费微赞助**,不是继续等。
- **问卷**:回收自助问卷(SURVEY1MON;访谈已 DROP→问卷)。定性输入来自问卷。
- **每周测量**:LS→Orders、PostHog funnel(按来源拆)、GSC。

### Track D — 发帖卫生(代码,~半天,非流量来源)
- **D1(本周做完)**:验证 9885f5b 的 OG 修复线上生效——/preorder、/word-to-color、几个 color/collection URL 过 Twitter Card Validator + FB Debugger、清缓存,确保创始人贴链接时预览卡是 PNG 不是空白。若 notes 帖要用,补 `app/notes/[slug]/opengraph-image.tsx`(复用 og-card.tsx);否则不做。
- ❌ 本期不做程序化 SEO(索引数周–数月,对 07-15 无效)。

### Track B — 把信号读干净(代码,~1 天,只留必要)
- **B-meas(唯一刚需,先做)**:funnel(`word_paywall_*`/`preorder_*`)+ first-party 事件端到端可读,**按来源/渠道拆**(这样才能识别"垃圾流量达标但 ICP=0")。建好退出门那张图。流量读不出 = 白冲。
- **B-其余(collections prop 瘦身 / posthog / B-conv)**:**本期不做**(降为 gate 后)。它们是回避分发的典型借口。posthog 任何改动必须保 pageview。

### Track C-spec — 一句话占位
- **本期不写完整 Auditor 规格**(给可能被砍的功能写 spec = busywork)。占位:gate 若为正,第一件事是 Auditor MVP(整盘 WCAG 扫描 + 色盲模拟 + 从档案给可访问替代色 + PDF 报告 + token 导出,复用 color-utils/colorblind/export)。完整 spec 只在窗口最后一周、信号已明确趋正时写。

## 5. 退出门 / 决策标准(~2026-07-15)—— **硬墙,零续命 + 渠道卫生**

**第一步 · 分母(加渠道卫生)**:窗口内 **≥ 500 合格 ICP UV 到 /preorder** 或 **paywall ≥ 1000**。读 PostHog 按来源拆——若 UV 主要是泛流量/免费工具围观,**不算合格分母**(没把对的人弄过来,读数无效)。

**第二步 · 决策矩阵:**
| 合格流量底线 | 真实刷卡预订(30 天) | 结论 |
|---|---|---|
| 达标 | **≥10** | ✅ 需求被验证 → 进 Track C,build Auditor(单点深做) |
| 达标 | **<10** | ❌ 产品没需求 → off-ramp(控成本维持 / 转移精力 / 打包评估) |
| **未达标** | 任意 | ❌ **判定:无法把对的人弄到付费面 = 获客失败。07-15 是硬墙,直接 off-ramp。不续窗、不再押。** |

> 去掉 v2 的"至多一次有界再押"——那是预先签好的失败许可。若 3.5 周内连 500 个对的眼球都弄不到,就是已经验证了"这个产品 + 你能执行的渠道"做不出获客,这本身就是结论。

**第三步 · 边界:** 7–9 笔(临界)看问卷——清晰 ICP + 共同强付费点可视情况判;≥10 但 ICP 分散 → 先锁买家类型。北极星 = 有证据支撑的 ICP + 真实付费。
