## §1 第 1 稿错在哪(评审的 + 我自己复核时找到的)

### 1.1 ✅ 采纳:我用 n=1 推翻了一整类解释,而我上一节刚说过 n 小不能下结论

第 1 稿 §1.3 写:「不肯用一个邮箱地址换的东西,不会有人用 ¥499 换。**这直接排除了
「墙上的文案没写好」这个解释**」。依据是 58 个回访被挡的会话里只有 1 个用了免费邮箱解锁。

**1/58 的 95%CI 是 (0.30%, 9.14%)。** 我在 §1.1 用 n=123 论证「1% 和 2% 分不开」,
**转头就用 n=1 宣布排除一个假设**。两位评审都抓到了,**完全成立**。

**改正**:免费解锁 1/58 只能说明「这条路没人走」,**不能区分**是「墙后的东西没价值」
还是「换邮箱这个交易本身让人反感」。**两种解释都还活着。**

### 1.2 ✅ 采纳:P1 的判据是未归一化的绝对数

第 1 稿把 P1 的成功判据写成「`color_copied` 21 天 17 → ≥40」。3.7 Flash 说得对:
**流量涨了这个数自己就会涨**。我在 §2.1 讲统计,却在判据里用裸计数,自相矛盾。
另外 3.1 Pro 指出 **26–39 这个区间我没定义怎么办** —— 也对。

### 1.3 🔴 我自己找到的(三家都没抓到):**`color_copied` 比我承认的更坏,整份计划都建在它上面**

第 1 稿 §5.1 只说了「选中文本复制不会触发」。实际读代码([copy-button.tsx:34-52](../src/components/copy-button.tsx#L34)):

```js
try {
  await navigator.clipboard.writeText(value);
  ...
  track("color_copied", ...);
} catch { /* noop */ }
```

**事件只在 `writeText()` resolve 之后才发。** 注释自己列了失败情形:权限被拒、
非安全上下文、**以及没有 clipboard API 的嵌入式 webview** —— 全部静默吞掉。
而 `/word-to-color/` 吃社交流量,**Instagram / X / LINE 的内嵌浏览器正是这一类**。

> **这是上一份计划 §2.5 那个 `track("export")` 错误的同一形状,只是这次出现在我自己的计划里,
> 而且是当核心论据用的。** 我在第 1 稿里写了半条免责声明就继续往上盖楼了。

**后果**:「带走率 2.8%」在一个**未知方向**上不可信 —— 我们分不清
「没人想带走」和「很多人点了但浏览器拒绝了」。**这两件事要做的改动完全不同。**

### 1.4 🔴 我自己找到的:**P1 的前提被数据证伪了**

第 1 稿 P1 写「六个 CopyButton = 六个决定,访客多半不知道选哪个」。
3.7 Flash 指出我没有任何点击分布证据。**我去取了,结论和我写的相反:**

| format | 事件 | 会话 |
|---|---:|---:|
| **hex** | **17** | **7** |
| Copy | 9 | 4 |
| swatch | 6 | 2 |
| palette / CSS / Config | 各 1–2 | 各 1–2 |

**`hex` 断层第一,没有选择瘫痪的迹象。** P1 那句话是我编的心理学叙事,**已删除**。

> 顺带发现一个埋点缺陷:一堆原始色值(`#FFB4C2` 等)被当成 `format` 上报。
> 来源是 `label={color.hex}` 且没给 `trackAs` 的六处调用
> (`color-decades-page.tsx:88`、`color-seasons-page.tsx:105`、`color-trends-page.tsx:98`、
> `combinations-page.tsx:71`、`color-industries-page.tsx:102`、`famous-palettes-page.tsx:96`)。
> `track()` 用的是 `trackAs ?? label`。word 页反而是对的(`trackAs="swatch"`)。

### 1.5 ⚖️ 部分采纳、部分驳回:免费额度

第 1 稿写「衰减平滑,没有断崖,5 次不是瓶颈,**不要动 `FREE_GENERATIONS`**」。
**「平滑」是错的**,我用的是事件计数;按**会话**取(21 天,362 个 word 会话):

| 最远用到第几次 | 会话 | 占比 |
|---|---:|---:|
| 1 | 146 | 40.3% |
| 2 | 61 | 16.9% |
| 3 | 42 | 11.6% |
| 4 | 27 | 7.5% |
| **5(上限)** | **86** | **23.8%** |

7.5% → 23.8% 是**在上限处的堆积**,不是衰减。**我的「不要动」没有依据,收回。**

**但两位评审的相反结论也都没有依据**,而且他们互相矛盾:
3.1 Pro 说「76% 用不完 → 免费层太慷慨」;3.7 Flash 说「24% 撞墙 → 这就是瓶颈」。
**上限处的堆积是上限的定义造成的** —— 你没法从堆积本身推出上限设得好不好。
**数据不决定这件事。** 三方(含我)都在这一点上过度解读了。

**新确立的事实是另一条**:**76.2% 的 word 会话根本走不到第 5 次** ——
付费墙对四分之三的使用者不存在。这是 3.1 Pro 的观察,成立。

(它挂在结果区下方,`wordHistory.length >= 2` 才出现)。
→ **已移入 W0**:先确认它可达,再谈「这个站的人不回答问题」。

## §2 约束(全部实测,决定了什么做不了)

**这份计划里没有一项 A/B 测试。** 严格说排除的是**功效合理的常规 A/B**;
1%→10% 那种量级几周就能看出来,**但这个站从来没出现过那种效应**(§1.8)。

### 2.2 「问用户」已经三次归零,不要再试第四次

| 尝试 | 曝光 | 回应 |

> 239 次曝光里 **0 作答 _且 0 关闭_** —— 一个连「关掉」都没人点的组件,
