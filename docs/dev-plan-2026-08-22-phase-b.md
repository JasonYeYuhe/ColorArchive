## §1 🔴 头条:§4 的判据**按构造就答不出来**

08-18 计划 §4 的信号阈值是「≥2 笔真实新增付费」。翻译成付费墙转化率:

| 量 | 值 |
|---|---:|
| `word_paywall_hit` | 91 会话 / 21 天 = **4.33/天** |
| 到判定日(08-22 → 09-15) | **24 天** |
| 预计撞墙数 | **~104** |
| **达到「≥2」所需的 撞墙→付费 率** | **1.92%** |
| 实测 撞墙→`pro_click` | **1.10%**(1/91) |
| 实测 撞墙→付费 | **0%**(0/91) |
| 0/91 的 95% 上界(rule of three) | **3.30%** |

**所需的 1.92% 落在实测置信区间 (0%, 3.30%) 的正中间。**
09-15 那天两个方向的结果都不是证据:0–1 笔既符合真实率 0% 也符合 1.9%;
≥2 笔既符合有信号也符合低转化率下的运气。

> **判据是欠功效的,不是数据还不够。** 唯一能让它可回答的量是**分母(撞墙次数)**,
> 而 B1/B2 改的是文案,不改分母。**做不做 B1/B2,09-15 的判定都不会更可信。**

**Codex 另外指出判据连口径都不对**:「≥2 笔」数的是**订单**,不是**首次付费的外部客户** ——
一个人买两次就能满足,而 Hayley 的**续费**也可能被算成「新增」。**这条成立,已记。**

### 2.5 🔴 各付费面的触达 —— 以及我犯的那个错

## §7 这份计划可能错在哪

1. **§1 的功效计算假设撞墙率不变(4.33/天)。** 分发侧一变就要重算。算法在 §1 表里,可复核。
2. **「停付费」≠「停项目」。** 别让它被读成后者。
3. **我和五份评审可能一起错在同一个地方**:都在用「转化率」框架看一个 500 会话/月的站。
   也许真问题不是「怎么让 500 人里有 2 人付费」,而是**「为什么只有 500」** ——
   那是分发问题,**五份评审没有一份认真谈过,本计划也没有。这是最大的盲区。**
4. **§2.5 暴露了一个更普遍的问题:这个站的付费面缺少「到达」埋点。**
   闸被看到/被挡住时不发事件,所以「有多少人碰到了付费面」这个最基本的问题,
   现在**答不出来**。要不要补,取决于 §4 的选择 —— 但**如果选了「停」,就别补**,
   那只会是又一次给没人走的路装计数器。
