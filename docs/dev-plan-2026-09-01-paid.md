### 0.2 服务器脚本改了必须手动部署 —— `git push` 不等于部署

`/root/ColorArchive` **没有 git remote**(2026-08-31 实测)。改 `server/` 下任何东西之后:

```bash
scp -o IdentityAgent=none -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes \
  server/<改过的文件> azureuser@172.207.80.109:/tmp/
ssh -o IdentityAgent=none -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes azureuser@172.207.80.109 \
  'sudo bash -c "cd /root/ColorArchive/server && cp -p <f> <f>.bak-$(date +%Y%m%d) && install -m 644 -o root -g root /tmp/<f> ./ && node --check <f> && md5sum <f>"'
```
**然后逐个 md5 与仓库比对。** 只有改了 `index.js` / 路由才需要 `pm2 restart`。

⚠️ **重启时间窗**:避开 **周一 03:00–03:59 UTC**(cache-warmer)和 **每天 09:00–09:59 UTC**
(COTD 邮件,`email-scheduler.js:193` 的小时闸 + 启动即跑一次)。

## §2 两个模型的评审,以及我改了什么

Gemini 3.1 Pro 与 3.7 Flash 各自独立评了第 1 稿。**两边独立收敛到同样几条,而且都对。**

### ✅ 采纳(改了)

1. 🔴 **「结账段 67% → 价格不是问题」是幸存者偏差。** 两边都指出:141/146 连 `/pro/` 都没点开,
   拿穿过 98% 流失后剩下的 3 个人推断「价格没挡住人」,和在珠峰顶上问「累不累」是一回事。
   **这个推断已撤回。** 价格是否是障碍,现有数据**无法回答**。
2. 🔴 **零续费有更简单的解释,而我选了更复杂的那个。** 我写「9 项权益全是解除限制」,
   两边都给出奥卡姆版本:**配色是项目制的一次性任务** —— 用户为某个项目配一次色,导出,
   项目进入下一阶段,几个月内不会再来。**这不是包装问题,是计费模式和使用频次的错配。**
   → 方向从「加独占功能」改为「先验证一次性收费形态」(见 W-2)。
3. 🔴 **押注 Figma 插件而没有任何遥测,是在重复本项目犯过的错。** 全库只有 7 条相关事件 ——
   等于不知道插件每天有几个人打开。**W-2 降级为「先花 1 小时加心跳埋点,3 天后看数再决定」。**
4. **判据设在了最弱的一档。** 我原本写「基线 3.4%,≥10% 成立」。蒙特卡洛实测(20,000 次):

   | 真实效应 | 期望 | 检出率 |
   |---|---|---:|
   | 无效应 | 5 vs 5 | 4.4%(假阳性,正常) |
   | 2× | 5 vs 10 | 25.6% |
   | **3×(=我设的 10% 线)** | 5 vs 15 | **64.5%** |
   | 4× | 5 vs 20 | 90.8% |

   → **不是纯噪声(两边都说过头了),但 64.5% 确实不够。** 判据已改(见 W-1)。
5. **运维排序错了。** Pro 说异地备份才是真 P0。采纳,**W-3 提到最前面**。

### ❌ 不采纳(有数据,不是嘴硬)

1. **Pro 说「加大 Pinterest 引流,期望值相当且买到信号密度」。**
   → **实测 30 天 Pinterest 带来 0 个会话**(同期 facebook 44、搜索 1,467)。
   它的期望值计算假设「1→8 pin = 3 倍流量」,但**这个渠道目前的产出是零**,
   8 倍工作量乘以零还是零。**Flash 的版本反而更对:该考虑的是砍掉它,不是加码。**
2. **Pro 说「账户门槛是转化杀手」。** → 结账是 LemonSqueezy **托管页直链,买 Pro 不需要注册**
   (`checkout-button.tsx:20` redirect mode)。「0 注册」说明的是别的事(见 §1.1 注)。
3. **Flash 说「立刻杀死 W1 和一切 A/B 幻想」。** → **前提不成立。**
   W1 的约束是「不要碰 `/guides/*`」,而本阶段的战场是 `/word-to-color/` 的付费墙 —— **不重叠**。
   而且 W1 已在跑、边际成本为零、对它自己的判据有 83.8% 功效(蒙特卡洛实测)。
   杀掉它只会丢掉已经花掉的工作和正在累积的数据。
4. **Flash 说「3 个付费用户,数据库丢了手写补偿都来得及,别花 3 天做容灾」。**
   → **严重低估。** 要保的不是 3 个客户,是**整张 events 表** ——
   这个项目所有决策(含正在跑的 W1)唯一的仪器。而且修它是 1 小时不是 3 天。

## §3 这一阶段做什么

### 🔴 先钉死判据的量级(上一阶段连续三次栽在这)

**唯一有体量的步骤是 `word_paywall_hit` = 146 会话/月。下游全部 N<6,不可测。**
本阶段**不做 A/B**(146 分两组 = 73/组/月,且会和 W1 抢分臂机制)。

### W-0 · 立刻做,1 小时,与商业无关但不做会丢一切

🔴 **备份没有异地副本。** `crontab` 每 6 小时备份到 `/root/ColorArchive/server/backups`,
**和数据库在同一块盘上**,cron 里没有任何上传;而 memory 记着「VM 无快照」。
台账写「ColorArchive 备份已在 Azure」——那是 DO 时代的配置,**迁移后没跟过来**
(和本次会话开头发现的「脚本没部署」是同一类问题)。

Azure 存储账号 `colorarchivestu` 已存在(rg `colorarchive-backups-stu`,japaneast)。
**做法**:在现有 `backup-sqlite.sh` 末尾加一步 `az storage blob upload`,保留最近 N 份。
**判据**:能从 blob 拉回一份并 `sqlite3 ... "PRAGMA integrity_check;"` 通过。

⚠️ **注意 Flash 认为这条不值得做**(「3 个付费用户丢了手写补偿都来得及」)。
**不采纳**:要保的是整张 events 表,它是本项目唯一的仪器,而且 W1 正在往里写。

### W-1 · 主要开发项:让撞墙的人知道 Pro 是什么

**问题**:146 个人撞墙,5 个去看了 `/pro/`,**0 个注册**。墙上只写 "Free preview limit",
没有在那一刻说明「Pro 能给你什么」。

**做什么**:在墙那一刻直接呈现权益 + 一个直达结账的入口(不需要先注册,结账本来就是托管直链)。
- ❌ 不要再加「页面加载即发」的事件(§0.1)
- ❌ 不要动 `word_generated` 的任何 props

**判据(已按实测功效调整)**:`word_paywall_hit` → 同会话内 `pro_click` 或到达 `/pro%`。
基线 **5/146 = 3.4%**,前后各 30 天。
- **≥13.7%(4×,约 20/146)= 成立** —— 这一档实测检出率 90.8%
- **≤6.8%(2×)= 不成立,停手**
- 中间(6.8%–13.7%)= **判为「未证实」而不是「成立」**,因为 3× 那一档只有 64.5% 检出率

🔴 **但这一条不要当成实验来做,当成 bug 来修。** 两个模型都指出:
墙不说明权益是**可用性缺陷**,不需要等 60 天读数才决定改不改。
**先改、先上线,前后对比只是事后的合理性检查,不是发布闸门。**

⚠️ **146 这个基数会被 W1 影响**(W1 若把更多内容页读者送进工具,撞墙的人会变多)。
读数时必须**分臂看,或等 W1 结束**。这是两个实验唯一会互相污染的地方。

### W-2 · 先测量,再决定(不是先开发)

**第一步(1 小时):给 Figma 插件加一条启动心跳** —— 匿名 ping + 版本号,不带任何用户标识。
全库现在只有 7 条相关事件,等于对插件一无所知。

**3 天后看数,然后二选一:**
- **日活 > 20** → 值得做插件内的 Pro 联动(Projects tab 已经需要 API key,是天然接点)
- **日活 < 5** → **彻底放弃插件方向**,不要再往里投商业化精力

**第二步(只有第一步给出正面信号,或 W-1 成立后):试一次性收费形态。**
两个模型独立收敛到同一点:配色是一次性任务,而我们在卖月订阅。
在 LemonSqueezy 加一个 **买断 / Day Pass** SKU,和现有月订阅并列展示,看撞墙的人选哪个。
**判据**:`checkout_clicked` 的绝对数(现在 3/月)。这是唯一一个「多一倍就看得见」的数。

### W-3 · 服务以 root 运行

`node /root/ColorArchive/server/index.js` 实测以 root 跑。属既有状况,不是今天引入。
降权到独立用户是标准做法,但涉及文件属主 + PM2 配置,**要能回滚、且在低流量时段做**。
**优先级低于 W-0**:备份丢了数据没了,提权是需要先有人来打你的前提。

## §4 明确不做的,以及为什么

### 🔴 先说清楚判据的量级问题,免得重蹈覆辙

上一阶段连续犯了三次同一类错误(基数没钉死就乘比率,见 `dev-plan-2026-08-31-next.md` §9.7/§9.10/§9.12)。所以先钉死:

下游全部 N<6,**任何针对结账段的改动都不可测**,不要为它们设计判据。

**并且这一阶段不做 A/B。** 理由:W1 已经占用了分臂机制(`ca_w1_v1`),

→ **判据一律用前后对比 + 明确的时间窗**,并接受它比 A/B 弱。

### W-1 · 主要开发项:让撞墙的人知道 Pro 是什么

**问题**:146 个人撞墙,5 个去看了 `/pro/`,0 个注册。墙本身写着 "Free preview limit",
但**没有把「Pro 能给你什么」放在那一刻**。

**做什么**(具体待定,由执行会话决定,但必须满足):
- 在墙那一刻直接呈现权益,而不是让用户自己去 `/pro/` 找

**判据**:`word_paywall_hit` → 同会话内 `word_paywall_pro_click` 或到达 `/pro%` 的比率。

比在网站上再加一道墙更可能带来第二个月的付费。

**判据**:这个不可测(N=3)。**用定性判据**:
先给现有 3 个付费用户发一封问「你为什么续/不续」的邮件 —— ⚠️ **需要 owner 单独授权**
(memory 记着「未发客户邮件(owner 未授权)」,这条至今有效)。

### W-3 · 运维两条(与付费无关,但今天发现,不修会一直悬着)

   **全在同一块盘上**,cron 里没有任何上传。台账写着「ColorArchive 备份已在 Azure」——
