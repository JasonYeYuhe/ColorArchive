## §1 分母已经存在 —— 要做的是**停止用错的那个**

第 1 稿说"第一方分析无法区分人和机器人"。**这句话只对 `pageviews` 成立。**

```sql
-- 没有访客标识,不可用作分母
CREATE TABLE pageviews (id, path, referrer, screen_width, created_at, channel, ...);

-- 有 session_id,而且事件是交互门控的 —— 这才是分母
CREATE TABLE events (id, event_name, props_json, user_id, session_id, path, ...);
```

**所以第 1 稿的 IP+UA 哈希、以及第 2 稿改用的 sessionStorage id,两个方案都在重造一个
已经存在的东西。** 都取消。

真正要做的三件事,都很轻:

1. **把所有报表的分母从 pageview 换成 `COUNT(DISTINCT events.session_id)`。**
   `server/` 里的周报、gate 报表、admin 面板都要改。
2. **确认 `server/bot-detect.js` 的过滤仍在工作**(07-26 部署,有 `[bot-filter]` 日志)。
   读一周日志,看丢弃率是否仍在合理区间。
3. **与 PostHog 的 session 数对表**(project 456902,**必须用 `query` schema**)。
   两边差异大就说明其中一套坏了,先修测量。

> **§1 未完成,§3 与 §4 一律不许开始。**

## §3 Phase 1 — 只测一个页面(第 2 周)

`/word-to-color/` 近 30 天 **488 个会话、4,872 个事件(每会话 10.0)** —— 按事件口径,
它既是最大的面,也是**唯一有真实使用深度**的面。guides 有 326 个会话但每会话只有 1.2 个事件。

07-27 那份文档已经追踪到三条真实路径,其中两条走到了 `/pro/`,最长一条 14 页:
apca 指南 → collections → word-to-color → contrast → **/pro/** → convert。
**所以 guides 不是没用,它是入口;word-to-color 是停留的地方。**

**不加功能,只装仪表**,回答:那些人走去了哪里。

1. 落地 → 输入第一个词
2. 输入 → 复制任一色值
3. 触发付费墙(第 5 个词)的绝对次数
4. 付费墙 → 点击 `/pro/`
5. 付费墙 → 邮件解锁
6. 单页跳出率

**完成判据**:一张从 landing 到 `/pro/` 的漏斗,每层有绝对数字,分母是 §1 校准过的会话数。

## §4 Phase 2 — 一次变现测试(第 3–4 周)

在 §3 漏斗最细的那一层做**一次**改动。流量不足以跑并行实验。

- **A. 若断在"输入 → 复制"** → 产品没被用起来,变现无从谈起,改工具本身。
- **B. 若断在"付费墙 → /pro/"** → 被用起来了但价格/时机/文案不对,改付费墙那一屏。

**判据必须提前写死**(Design Notes 的退役之所以干净,就是因为规则是提前写的)。

> **窗口按会话数走,不按天数走:累计 600 个 word-to-color 会话为一轮。**
> 若这 600 个会话里 `/pro/` 点击的转化率 < 0.5%(即 0–2 次),判定失败。

**为什么按会话不按天:** 真实规模是每月约 1,270 个会话,word-to-color 约占一半 ——
**14 天只能攒到约 300 个会话**,而 300 个样本连 0.5% 和 0% 都分不开。按天数设窗口
会逼着你在样本不足时下结论,那正是 2026-07-26 那次错误的形状。600 会话大约需要
**4–6 周**,这是这个站的规模决定的,不是耐心问题。

**必须诚实地说清这个测试能证明什么:** 在这个量级上,它**只能证伪,不能证实**。
0/600 可以判定"低于 0.5%";但要区分 0.4% 和 0.8% 需要数千个会话,这个站一年也攒不到。
**所以 §5 的"深耕"分支不能只靠这个测试触发,必须有真实付费。**

## §5 决定,规则提前写好

**判据锚定"MRR vs 月烧钱"(§2.0 的数字),不是订单笔数。** 第 1 稿写的"≥3 笔非试用付费"
是拍脑袋的:3 笔 ¥299 的订单对上 $80/月的成本,继续投入是亏的。

| 路 | 触发条件 |
|---|---|
| **深耕** | 出现 **≥3 笔真实付费**(非试用、非测试、未退款),**且** MRR ≥ 月烧钱 × 0.5 |
| **转公用事业** | 未达上条,**且**真实会话 ≥ 800/月(即维持当前量级) |
| **收缩** | 未达上条,**且**真实会话连续两个月 < 400 |

> **阈值按真实规模重设。** 第 2 稿写的是"≥5,000 会话/月转公用事业,否则收缩" ——
> 而真实是每月约 **918–1,270**。**按那份判据,这个站会被自己写的规则直接判收缩。**
> 那个 5,000 是我凭空拍的,和这个站的量级差五倍。这是第 2 稿最严重的错误。
>
> "深耕"回到看真实付费而不是看转化率,原因见 §4:这个量级的转化率测试只能证伪。

**"转公用事业"和"收缩"都必须有可执行蓝图**,不能只是一个词:
- **公用事业**:静态化(SSG + 扁平 JSON),迁到免费层(Cloudflare Pages / R2),
  关停 droplet 与后端 AI,保留域名与 SEO 资产。目标月成本 < 一杯咖啡。
- **收缩**:同上,并关停付费链路、下架商店产品、停止一切内容生产。
