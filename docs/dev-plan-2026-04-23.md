## 2. 2026-04-22 意见书未覆盖 / 低估的风险（Codex 本次补充）

### NEW-P0-A：LS 账户 UI 契约已断裂

- [src/components/account-page.tsx:149-155](../src/components/account-page.tsx) 期望 `sub?.stripeCustomerId`，并以此 gate "Manage billing" 按钮（:171-172）。
- [server/routes/me.js:93-101](../server/routes/me.js) 只返回 `provider / plan / status / proExpiresAt`，**根本不返回 `stripeCustomerId`**。
- 后果：**所有 LS 订阅用户在账户页看不到"管理订阅"入口**，只能靠邮件里的 LS portal 链接。这是活生生的产品漏洞，不只是文档不一致。

**修法**：
1. 后端 `/me` 增加 `providerCustomerId`（LS 存 `customer_id`，Apple 存 `original_transaction_id`，Stripe 存历史字段）。
2. 前端改成按 `provider` 分发：LS → LS customer portal；Apple → 跳到 iOS Settings subscription；Stripe → 旧链路。
3. 加单测覆盖 `/me` 返回形状。

### NEW-P0-B：iOS StoreKit payload 字段名风险

- [iOS/ColorArchive/Services/StoreManager.swift:163-168](../iOS/ColorArchive/Services/StoreManager.swift) 发送 `transaction.jsonRepresentation`。
- [server/routes/auth.js:264-266](../server/routes/auth.js) 注释写"expects JWS from `Transaction.jwsRepresentation`"。
- [server/apple-jws.js:99-117](../server/apple-jws.js) 按 compact JWS 三段式解析。
- `jsonRepresentation`（StoreKit 2 Transaction 的 JSON dump）≠ `jwsRepresentation`（JWS 串）。如果两边真的不一致，**所有 iOS IAP 将返回 403**，直接堵死 Apple 侧收入。
- 由于 v1.1 build 2 已经过审（memory 记录 2026-04-01 submitted），且没有用户反馈"买不了"，合理怀疑是两种情况之一：(a) iOS 端 `jsonRepresentation` 在当前 SDK 下其实就是 JWS 字符串；(b) IAP 从未被真实用户跑通过。

**修法**：
1. 本地 StoreKit sandbox 跑一次真实购买，抓 payload，确认字段是 JWS 还是 JSON。
2. 如果是 JSON，改 iOS 端为 `transaction.jwsRepresentation`，发一版 v1.2 hotfix。
3. 后端加 defensive 解析：`split('.')` 长度不是 3 时返回明确错误码 `INVALID_RECEIPT_FORMAT` 而不是 403。

### NEW-P0-C：Color 详情页从"全量静态"切换到"动态代表集"但无缓存监控

- [app/colors/[slug]/page.tsx:32-35](../app/colors/[slug]/page.tsx) 注释明确说"为避开 Vercel 80 MB 输出限制，只预渲染代表子集"。
- [app/colors/[slug]/page.tsx:20](../app/colors/[slug]/page.tsx) `dynamicParams = true`，长尾 4000+ 颜色页走按需渲染。
- 问题：Vercel Edge Cache 命中率、冷启动延迟、成本都没有观测。2026-04-22 意见书仅指出 3.2 GB `out/` 目录，但真正的风险已经从"部署太大"切换成"长尾 SSR 命中不稳定"。

**修法**：
1. 加一条 scheduled job：周一凌晨对长尾 color slug 做 cache warm（curl HEAD 扫一遍）。
2. 在 `app/layout.tsx` 的 `PageTracker` 里增加 `x-vercel-cache` header 上报。
3. 监控 P95 TTFB，超过 600ms 报警。

### NEW-P1-A：Instagram webhook POST 未鉴权

- [server/routes/instagram.js:457-461](../server/routes/instagram.js) POST 只写 log，无 `x-hub-signature-256` 校验。
- 2026-04-08 审计 + 2026-04-17 Pinterest 修复覆盖了 LS 和 Pinterest，但 Instagram 漏了。
- 暴露面：任何人可以伪造 IG 事件往数据库灌脏数据（如果有落库）或 DoS。

**修法**：加 `x-hub-signature-256` HMAC 校验，使用 `FB_APP_SECRET`。参考 Pinterest 修复的 PR。

### NEW-P1-B：Sandbox / Production StoreKit 边界不清

- [server/routes/auth.js:279-371](../server/routes/auth.js) 存储了 `is_sandbox` 但策略上没区分：sandbox 购买也会 `tier = 'pro'`。
- TestFlight 场景下这是 intentional 的，但线上环境如果收到 sandbox JWS 也会升级为 Pro，等于免费 Pro 漏洞。

**修法**：生产环境拒绝 sandbox JWS（或只允许 admin allowlist 账号）；在 `server/apple-jws.js` 里直接返回 tier 时带上 env 标记。

### NEW-P1-C：SQLite 备份路径三处不一致

- 应用写 [server/db.js:4](../server/db.js) → `server/data.db`
- [scripts/backup-sqlite.sh:17](../scripts/backup-sqlite.sh) 默认 `/root/colorarchive-api/data/colorarchive.db`
- [docs/ls-commerce-validation-2026-04-17.md:206](../docs/ls-commerce-validation-2026-04-17.md) 说 `/root/ColorArchive/server/data.db`
- 三处两两不同。要么备份备的是空路径（cron 默默跑了个空壳），要么 docs 错。
- **现在就应该 SSH 上去 `ls -la` 一次**，确认实际生产路径，并把三处收敛成一个常量。

### NEW-P1-D：Sitemap ↔ robots 冲突

- [app/sitemap.ts:61-70](../app/sitemap.ts) 包含 `/favorites/` `/recent/` `/palette/`
- [app/robots.ts:16-18](../app/robots.ts) Disallow 这同一批路径
- 要么 sitemap 撤出（它们本就是用户个人页，不应被索引），要么 robots 放开。2026-04-22 意见书整个没提到。

### NEW-P1-E：Collection 文案引用并不存在的 color ID

- [src/lib/collections.ts:1265](../src/lib/collections.ts) 正文提"amber-glow-soft"，但 palette 数组里是 `amber-bloom-soft`
- :1285 正文提 `pearl-blush-soft / slate-veil-muted / obsidian-tone-soft`，palette 实际是 `blush-pearl-soft / cobalt-veil-muted / cobalt-ink-soft`
- 对用户不会 build fail（文案只是字符串），但会出现"你在正文里读到的颜色点开搜不到"的尴尬。
- 需要一条"collection prose lint"脚本。

### NEW-P1-F：无错误观测

- 全项目 `rg "Sentry|@sentry"` 无结果。
- 只有 Vercel Analytics + 自建 `/pageviews`。
- 后端 Express 异常、前端 unhandled rejection、iOS 崩溃，全都没有上报通道。对一个已经卖钱的产品，这是硬伤。

### NEW-P1-G：Checkout 无事件埋点

- [src/components/checkout-button.tsx:28-35](../src/components/checkout-button.tsx) 不调用 `/events`，但 [server/routes/events.js:17-40](../server/routes/events.js) 基础设施已经在。
- 结果：我们根本不知道"多少人点了 checkout 没转化"。无漏斗，无优化依据。

### NEW-P2：Google OAuth .org 白名单仍待人工操作

- [docs/oauth-redirect-fix-plan.md](./oauth-redirect-fix-plan.md) 从 04-20 起就挂着"3 分钟人工动作"，3 天没做。
- 每天每个点 Google 登录的用户都会撞 error 400。优先级应该比这份计划书里任何代码任务都高，但它不是"开发"，是点开 GCP Console 加一行。

## 4. 建议新增功能（收敛口径：必须能转化为付费）

**前提**：ColorArchive 当前最不缺的是"再来一个颜色小工具"。新功能必须同时满足：
- 能复用 5,446 色数据的**唯一性**（别人复制不了）
- 有明确的"免费预览 → Pro 解锁 → Team 升级"漏斗
- 能在 1-3 周内做出可卖的 MVP

### 功能 A：Palette Audit Report（最推荐）

**场景**：用户粘贴一份 token JSON / 上传 CSS / 贴 Tailwind config → 后端提取所有颜色 → 每个颜色找到 ColorArchive 最近命名 → 检测重复、微小差异、WCAG 失败对、色盲冲突 → 导出 PDF（branded，含 remediation 建议）。

**为什么会付费**：
- 设计系统 owner / 前端 lead 每次 "audit 自己的 token" 都是手工苦活。
- 5,446 色的稠密 lattice 意味着我们能给出**具名近似色**（"你这个 #C23A4B 其实就是 Scarlet Core Vivid，建议换成系统色"），而不是泛泛建议。
- Free: 3 次/月，水印 PDF；Pro: 无限 + 无水印；Team（新）: branded PDF + GitHub PR 导出。

**工期**：1.5-2 周 MVP。复用 [src/lib/color-utils.ts](../src/lib/color-utils.ts) 的最近色算法、[src/components/wcag-audit-page.tsx](../src/components/wcag-audit-page.tsx) 的对比度引擎、[src/lib/guides.ts](../src/lib/guides.ts) 的修复话术。

### 功能 B：Seasonal Token Swap

**场景**：已经买了 palette pack 的用户，点"应用到我的 token"→ 上传当前 token → 选季节（Spring 2026 / Dark Mode / A11y Repair）→ 预览每个 token 的 before/after → 自动跑对比度回归 → 导出 Tailwind / CSS vars / Style Dictionary patch。

**为什么会付费**：把 palette pack 从"一次性买断的 zip"升级成"可复用的 transform"，让老用户有理由再买下一个 pack。**转化路径**：免费用户用 MVP 版 → 撞到"导出需要 Pro" → 升级。

**工期**：2-3 周。重用 [src/components/token-generator-page.tsx](../src/components/token-generator-page.tsx)。

### 功能 C：Industry Palette Brief Generator

**场景**：自由品牌设计师给客户做提案。选行业（SaaS / Healthcare / Luxury / Fintech 已有数据）→ 回答 5 个约束（调性、主色偏好、禁忌、深色模式、国际化）→ 生成 3 个候选 palette + rationale + WCAG 配对 + 禁用场景 → 导出 1 页 PDF brief。

**为什么会付费**：**替代自由设计师 30 分钟做提案的工作量**。定价：免费 1 次预览水印，Pro 无限，按份 $19 单次购买（针对偶尔用的人）。

**工期**：1 周。重用 [src/lib/color-industries.ts](../src/lib/color-industries.ts) 和现有 collections。

### 功能 D：Team Workspace（非 MVP，中期方向）

- 共享 palette 库
- 品牌 guardrail（锁定主色不允许改）
- 席位 / 角色 / 审批流
- 与 Figma Plugin（我们已经有 stub）对接

**为什么会付费**：客单价从个人版 ¥499/mo 跳到团队版 ¥999+/mo/seat。ColorArchive 现在缺的就是客单价。

**工期**：4-6 周。**不建议进本轮 4-6 周计划，放 Q3**。

### 功能 E：Creative Pack Builder（次推荐）

Pinterest + Instagram 的 autopilot 已经在跑。把它产品化：用户选 collection → 选模板（9 宫格 / Story / Reel）→ 自动生成资源 + 安排发布 + 追踪从图片回到 collection 的点击。

**工期**：1.5 周。复用 [server/pinterest-admin.js](../server/pinterest-admin.js)。
