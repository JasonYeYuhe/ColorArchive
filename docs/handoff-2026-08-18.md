## 这个仓库已经证明过的坑(全踩过,别再踩)

1. **`pageviews` 表任何一列都不能当证据,包括 referrer。** 22.5% 是自动化;
   它的 referrer 列曾把一个机器人报成「580 次 Google 引荐」,我据此恢复了 8 篇文章,
   GSC 一查是 0 点击 0 曝光,全部撤回。**判断 URL/需求价值只有 GSC 能回答。**
   GSC 入口:`https://search.google.com/u/1/search-console?resource_id=sc-domain%3Acolorarchive.org`
   (**必须 `/u/1/`**,`/u/0/` 是另一个没权限的账号)。
2. **只跑 typecheck 不够。改 hook 必须 `npx eslint <改动的文件>`**(全量 lint 会超时)。
   根布局组件里早返回写在 hook 之上 = 全站白屏。**监听器要在 effect 内跳过,`return null` 拦不住 effect。**
3. **写完守卫要把缺陷放回去,确认它真的会红,再撤回。** 这一轮四个守卫都是这么验的。
4. **验证一个实例不能推广到全部。** 我差点发出「57% 事件没有 session_id」,
   实际是 30 天窗口跨在埋点上线日两侧,干净窗口是 7/2418。
5. **client 组件不能值导入带数据的模块**(`newsletter-issues.ts` import 了整份 JSON,
   `"use client"` 里值导入会把数据集打进 bundle —— `96ff99e` 已经踩过一次,两个 1.38MB chunk)。
   纯函数放没有数据的模块里(见 `src/lib/newsletter-date.ts` 的注释)。
6. **修 A 之前先问会不会弄坏 B。** 这轮修 `$3.47→$0.03` 时,如果只改前端不改
   `admin.js` 的两个订单查询,会把后端弄坏。
