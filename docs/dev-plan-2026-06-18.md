## 5. 退出门 / 决策标准(~2026-07-15)—— 复合指标(数量 × 流量基数)

> **Gemini review 的核心修正**:`<10 笔` 单看分子无法执行。没有流量基数,你分不清"产品没人要"还是"根本没人看到"。必须先看分母。

**第一步 · 分母(有效验证前提)**:窗口内付费面要拿到足够"合格眼球",读数才有意义。
- 流量底线 ≈ **`/preorder/` UV ≥ 500** 或 **paywall 触发 ≥ 1000**(任一达标 = "本次验证有效")。

**第二步 · 决策矩阵:**

| 流量底线 | 真实刷卡预订(30 天) | 结论 |
|---|---|---|
| 达标 | **≥10** | ✅ 需求被验证 → 进 Track C,建 Auditor(单点深做) |
| 达标 | **<10** | ❌ 产品没需求 → 果断 off-ramp(维持 / 转移精力 / 打包评估) |
| **未达标** | 任意 | ⚠️ 死因是**分发无能,不是产品** → 不归咎产品:延长窗口 / 检讨并重押分发渠道;若确实无获客能力,据此判项目"因获客失败"而非"产品失败" |

**第三步 · 质量 × 数量的边界裁决(避免模糊读数时拍脑袋):**
- **7–9 笔(临界)**:不机械杀。看 10 访谈——若浮现清晰 ICP + 共同强付费点,可再延一个窗口复测;否则按 `<10` 处理。
- **≥10 笔但访谈显示 ICP 完全分散**:数字可信度打折——可建 Auditor MVP,但**先锁定那一类买家**再做,不能当"广谱需求"铺开。
- 北极星 = **有证据支撑的 ICP + 真实付费**,不是单一数字。
